# AGENTS.md

## Режим работы по умолчанию

Пользователь не обязан каждый раз напоминать, какие skills или tools использовать.

Для каждой задачи агент обязан самостоятельно:

1. Прочитать AGENTS.md.
2. Определить тип задачи.
3. Выбрать нужные `.skills/*/SKILL.md`.
4. Решить, нужны ли MCP tools или браузерная проверка.
5. Если задача связана с UI — использовать доступный способ браузерной проверки:
   - сначала Playwright MCP, если он виден;
   - если MCP недоступен — Playwright CLI / Microsoft Edge;
   - если браузерная проверка невозможна — честно написать об этом.
6. Если задача связана с OpenAI/Codex/API/MCP/models/tools — использовать `openaiDeveloperDocs`.
7. Если задача связана только с документацией или простыми текстовыми файлами — MCP можно не использовать.
8. Если задача связана с RAG/backend — сначала использовать соответствующие skills, а MCP только если он реально нужен для проверки.
9. Не ждать, что пользователь отдельно напишет "используй skill" или "используй MCP".

После выполнения задачи агент обязан кратко указать:

- какие skills использовал;
- какие MCP/tools использовал;
- если MCP/tools не использовал — почему они были не нужны;
- какие файлы изменил;
- как проверить результат.

Ограничения:

- PostgreSQL MCP сейчас не использовать.
- Qdrant MCP сейчас считать отложенным экспериментом и не использовать в обычных задачах.
- Figma/Canva использовать только для UI/UX задач по явной необходимости.
- Не удалять данные без явного подтверждения.
- Не отправлять рабочие документы АСУ ТП во внешние сервисы.

## Назначение

Этот репозиторий собирается как локальная база знаний и консультант по рабочим документам АСУ ТП.
Система должна работать на текущем слабом ноутбуке и без переделки переноситься на более мощный ПК.

## Что это за проект

Стек проекта:

- `Open WebUI` как основной локальный чат-интерфейс
- `Ollama` как локальный провайдер моделей
- `kb-api` как API для импорта, поиска, ответов и служебных страниц
- `PostgreSQL` для метаданных, статусов задач и журналов
- `Qdrant` для векторного поиска
- `ingestion-worker` пока как каркас, основная логика сейчас в `kb-api`

## Текущая рабочая конфигурация

- Чат-модель: `qwen3:4b`
- Embedding-модель: `qwen3-embedding:0.6b`
- Платформа: Windows + Docker Desktop + WSL2
- Основной порт `kb-api`: `http://localhost:8787`
- Open WebUI: `http://localhost:3000`

## Что уже реализовано

- Импорт файлов из `data/raw`
- Поддержка `.txt`, `.md`, `.pdf`, `.docx`, `.csv`, `.xlsx`, `.xls`
- Chunking документов
- Индексация в PostgreSQL + Qdrant
- Semantic + lexical поиск
- Ответы по найденным источникам
- Поиск по PDF-страницам
- Классификация страниц PDF:
  - `title`
  - `contents`
  - `changelog`
  - `legal`
  - `signals`
  - `table`
  - `scheme`
  - `screen`
  - `text`
- Фильтры по:
  - документу
  - типу страницы
  - инженерной теме
  - тегу/сигналу
- Браузерные страницы:
  - `/ui/consult`
  - `/ui/ingest`
  - `/ui/pages-search`
  - `/ui/jobs`
  - `/ui/v2/chat` — новый UI, итерация 1: страница чата с историей и фильтрами;
    с итерации 3 — переключатель «🔒 Локально / ⚡ Облако» в шапке
  - `/ui/v2/knowledge` — новый UI, итерация 2: дерево разделов, загрузка,
    задачи импорта, таблица документов с тегами и перемещением
  - `/ui/v2/settings` — новый UI, итерация 3: настройки облака
    (OpenAI-совместимого провайдера), темы по умолчанию, обслуживание базы.
    Подробности по облаку — `docs/CLOUD_PROVIDER.md`. Эмбеддинги всегда
    локальные (`qwen3-embedding:0.6b`); в облако могут уйти только чанки,
    отобранные локальным retrieval.
  - Старые `/ui/consult`, `/ui/ingest`, `/ui/jobs`, `/ui/pages-search`,
    `/ui/nodes` скрыты за `?admin=1` (cookie `admin_mode=1`, TTL 1 час).
    В сайдбаре нового UI есть ссылка «Админ-режим (старый интерфейс)».
- Фоновый импорт:
  - `/documents/ingest-file-async`
  - `/documents/ingest-folder-async`
- Защита от дублей уже индексированных файлов
- Очистка дублей через UI/API
- Прогресс задач импорта:
  - `total_items`
  - `processed_items`
  - `progress_message`
- Лёгкий режим импорта:
  - `createVisualAssets=false` для тяжёлых PDF
- Управление задачами:
  - `Остановить`
  - `Повторить`
- Защита от пустых ответов без источников:
  - `fallback-empty`

## Главные пользовательские требования

- Всё локально, без облака
- Русский интерфейс и русские служебные тексты
- Нужен практический консультант по рабочим документам, а не “универсальный агент ради агента”
- Важны PDF, схемы, таблицы, теги, сигналы, оборудование, документация АСУ ТП
- Нужно уменьшать число повторных объяснений, поэтому документация в репозитории обязательна

## Важные ограничения текущего ноутбука

- Слабый CPU
- Нет нормальной дискретной GPU
- Ограниченный диск `C:`

Практический вывод:

- большие PDF надо импортировать в фоне
- для больших папок сначала лучше делать текстовый проход без превью страниц
- мультимодальный поиск по картинкам добавлять позже, после стабилизации текстового слоя

## Главная проблема, уже найденная в работе

На `2026-04-23` тяжёлый импорт падал не из-за модели, а из-за нехватки места на диске.
Qdrant возвращал ошибку вида:

- `No space left on device: WAL buffer size exceeds available disk space`

После очистки безопасных кэшей место на `C:` было восстановлено примерно до 10 ГБ.

## Как правильно работать дальше

### Нормальный запуск

1. Убедиться, что Docker Desktop запущен и `docker-desktop` в WSL имеет состояние `Running`
2. Запустить проект командой:
   - `scripts/start.ps1`
3. Проверить:
   - `http://localhost:8787/health`
   - `http://localhost:8787/ui/jobs`
   - `http://localhost:8787/ui/ingest`
   - `http://localhost:8787/ui/consult`
   - `http://localhost:8787/ui/pages-search`

### Как правильно импортировать реальную папку

Для большой папки документов сначала использовать:

- фоновый импорт
- без создания preview страниц

То есть:

- папка: `КС новая/Документация metsoDNA CR/2 Функциональные блоки`
- режим: `createVisualAssets = false`

После успешного первого прохода можно точечно переиндексировать нужные PDF уже с preview страницами.

### Где смотреть статус

- `http://localhost:8787/ui/jobs`

Там важны поля:

- статус
- прогресс
- документ
- ошибка

### Как спрашивать по базе

- основной рабочий режим: `http://localhost:8787/ui/consult`
- если вопрос общий по документу, использовать `Все источники`
- если нужен только текст, переключаться на `Только текст`
- если нужны содержания, схемы или страницы, переключаться на `Только PDF-страницы`

Нормальное поведение:

- если релевантные источники есть, система отвечает по ним
- если релевантных источников нет, система возвращает честный пустой результат, а не выдумывает ответ

## MCP tools

В проекте подключены MCP tools для повышения продуктивности Codex/агента.

## Актуальный статус MCP

- `openaiDeveloperDocs` — работает и используется для OpenAI/Codex/MCP/API/models/tools.
- `playwright` — может быть недоступен как отдельный MCP namespace в Codex Extension; для UI-проверок разрешён fallback через Playwright CLI / Microsoft Edge.
- `tavily` — работает как MCP через прямой MCP protocol. Доступные tools:
  - `tavily_search`
  - `tavily_extract`
  - `tavily_crawl`
  - `tavily_map`
  - `tavily_research`
  Может не отображаться как отдельный tool namespace, но его можно использовать для интернет-исследований.
- `qdrantMemory` — работает как MCP через прямой MCP protocol. Доступные tools:
  - `qdrant-store`
  - `qdrant-find`
  Использовать только для отдельной коллекции `mcp-agent-memory`.
- Рабочие RAG-коллекции проекта через Qdrant MCP не трогать.
- PostgreSQL MCP сейчас не использовать.
- Figma/Canva использовать только для UI/UX задач по явной необходимости.

## Когда использовать Tavily

Использовать `tavily` для:

- поиска UI/UX референсов;
- исследования современных SaaS/AI workspace/document search интерфейсов;
- поиска YouTube/FOHOW/маркетинговых материалов;
- поиска международных источников на разных языках;
- сбора ссылок, описаний, сравнений.

## Когда использовать Qdrant MCP

Использовать `qdrantMemory` только как память агента / экспериментальную отдельную коллекцию:

- сохранять полезные заметки по проекту;
- искать ранее сохранённые заметки;
- не использовать для диагностики рабочей RAG-базы;
- не удалять и не пересоздавать коллекции;
- не писать туда рабочие документы АСУ ТП.

Практический вывод:

Для текущей локальной разработки основной рабочий набор: AGENTS.md + .skills + openaiDeveloperDocs + браузерная проверка через Playwright CLI/Edge.

Для интернет-исследований агент должен использовать Tavily MCP, если задача требует поиска референсов, сайтов, YouTube-каналов или международных материалов. Для памяти агента можно использовать qdrantMemory только в коллекции mcp-agent-memory.

Правила использования MCP:

- Перед изменением кода сначала прочитать AGENTS.md и нужные `.skills/*/SKILL.md`.
- `openaiDeveloperDocs` использовать только как справочник по документации OpenAI.
- `playwright` MCP использовать для UI smoke-test и проверки страниц после изменений, если он доступен в текущем окружении.
- Если Playwright MCP недоступен в Codex Extension, использовать Playwright CLI с установленным системным браузером, например Microsoft Edge.
- Не использовать MCP для удаления данных без явного подтверждения.
- Не отправлять рабочие документы АСУ ТП во внешние сервисы.
- PostgreSQL MCP сейчас не использовать.
- Qdrant MCP не использовать для рабочей RAG-базы проекта.
- Qdrant MCP считать отложенным экспериментальным инструментом памяти агента, только для отдельной коллекции `mcp-agent-memory`.
- Figma/Canva tools использовать только для UI/UX задач по явной необходимости.

### Автоматический выбор инструментов

Агент должен сам решать, нужен ли MCP или другой инструмент проверки.

Правила:

- Если задача связана с OpenAI API, Codex, MCP, models, tools, Responses API или официальной документацией OpenAI — использовать `openaiDeveloperDocs`.
- Если задача связана с локальным UI, страницами `/ui/consult`, `/ui/ingest`, `/ui/jobs`, `/ui/pages-search`, `/ui/v2/*`, проверкой после UI-патча или ошибками интерфейса — сначала использовать `playwright` MCP.
- Если Playwright MCP недоступен в текущем окружении, использовать Playwright CLI с установленным системным браузером, например Microsoft Edge.
- Если браузерная проверка невозможна, честно написать, что нужна ручная проверка в браузере.
- Если задача только по текстовым файлам, README, AGENTS.md, SKILL.md или простой документации — MCP можно не использовать.
- Если задача связана с кодом, сначала читать AGENTS.md и нужные `.skills/*/SKILL.md`, потом решать, нужен ли MCP или браузерная проверка.

После выполнения задачи агент должен кратко написать:

- какие MCP или инструменты проверки использовал;
- почему использовал именно их;
- если MCP не использовал — почему он был не нужен или недоступен.

Ограничения:

- Не использовать MCP или CLI-инструменты для удаления данных без явного подтверждения.
- Не отправлять рабочие документы АСУ ТП во внешние сервисы.
- PostgreSQL MCP сейчас не использовать.
- Qdrant MCP не использовать для рабочей RAG-базы проекта.
- `qdrantMemory` использовать только как память агента через отдельную коллекцию `mcp-agent-memory`.
- Qdrant MCP можно рассматривать только как отложенный экспериментальный инструмент памяти агента, не как инструмент диагностики рабочей RAG-базы.
- Figma/Canva tools использовать только для UI/UX задач по явной необходимости.

## Skills для Codex/агента

В проекте есть каталог `.skills` с отдельными инструкциями для разных типов задач.

Перед изменением кода агент должен:

1. Определить тип задачи.
2. Открыть `.skills/README.md`.
3. Выбрать подходящий skill.
4. Прочитать соответствующий `.skills/*/SKILL.md`.
5. Только после этого предложить план изменений.

Если задача затрагивает несколько областей, нужно использовать несколько skills.

Основные skills:

- `.skills/rag-system/SKILL.md` — общая RAG-архитектура, ответы по источникам, fallback-empty.
- `.skills/document-ingestion/SKILL.md` — импорт документов, PDF, DOCX, XLSX, jobs, page_type.
- `.skills/vector-search/SKILL.md` — Qdrant, embeddings, semantic/lexical/hybrid search.
- `.skills/local-llm-agent/SKILL.md` — Ollama, Open WebUI, prompt building, qwen3:4b.
- `.skills/security-and-privacy/SKILL.md` — локальная приватность, логи, внешние API, секреты.
- `.skills/operations-troubleshooting/SKILL.md` — запуск, Docker, WSL2, health, jobs, Qdrant/PostgreSQL.
- `.skills/project-documentation/SKILL.md` — документация проекта, README, docs, фиксация изменений.
- `.skills/testing-quality/SKILL.md` — smoke tests, regression checks, проверка импорта, поиска и ответов.
- `.skills/ui-ux-design/SKILL.md` — UI/UX, дизайн страниц, удобство интерфейса, русские тексты, состояния загрузки и ошибки.

Примеры выбора skills:

- плохой ответ по документам → rag-system + vector-search + local-llm-agent + testing-quality
- не импортируется PDF → document-ingestion + operations-troubleshooting + testing-quality
- ошибка Qdrant или нехватка места → operations-troubleshooting + vector-search
- изменение prompt-а → local-llm-agent + rag-system + testing-quality
- добавление OCR → document-ingestion + security-and-privacy + testing-quality
- улучшение дизайна /ui/consult → ui-ux-design + rag-system + local-llm-agent + testing-quality
- улучшение /ui/ingest → ui-ux-design + document-ingestion + testing-quality
- улучшение /ui/jobs → ui-ux-design + operations-troubleshooting + testing-quality
- обновление документации после изменения кода → project-documentation + testing-quality
- проектирование новой UI-страницы → ui-ux-design + project-documentation + testing-quality

Правило:
если агент не уверен, какой skill нужен, он должен сначала открыть `.skills/README.md`.
