# Облачный ИИ (OpenAI-совместимый провайдер)

## Что делает

Позволяет подключить любой OpenAI-совместимый API (DeepSeek, OpenRouter, Groq,
Together, Mistral, локальный LM Studio и т.д.) и использовать его для генерации
ответов в чате вместо локальной Ollama. Эмбеддинги всегда остаются локальными —
облако используется только для генерации текста ответа.

Включается в `/ui/v2/settings` и активируется по выбору в чате: переключатель
**🔒 Локально / ⚡ Облако** в шапке страницы `/ui/v2/chat`. Выбор сохраняется
на уровне сессии (`chat_sessions.provider`).

## Что попадает во внешний API при использовании

- Системный промпт (текст инструкции для модели).
- Последние 6 сообщений из истории чата (`role: 'user'` и `role: 'assistant'`).
- Текущий вопрос пользователя.
- Содержимое найденных чанков (фрагменты документов), которые отобрал
  локальный retrieval. По умолчанию — до 6 чанков, каждый обрезается до
  1200 символов.

## Что НЕ попадает во внешний API

- Эмбеддинги. Они всегда строятся локальной моделью `qwen3-embedding:0.6b`.
- Полные документы. Только фрагменты, которые попали в выборку retrieval.
- Метаданные документов (если они не процитированы в выбранных чанках).
- Логи и статистика kb-api.
- Другие сессии чата, к которым этот запрос не относится.

## Как настроить

1. Открыть `http://localhost:8787/ui/v2/settings`.
2. В блоке «Облачный ИИ» заполнить:
   - **Название провайдера** — свободный текст, например `DeepSeek`.
   - **Base URL** — корень API, например `https://api.deepseek.com`.
     Допустимо указывать без `/v1` — он будет добавлен автоматически.
     Если ваш провайдер требует другой путь (`/v2/chat/completions` и т.п.),
     укажите его в Base URL целиком — клиент уважает указанный путь.
   - **API Key** — ключ доступа, передаётся как `Authorization: Bearer ...`.
   - **Модель** — имя модели у провайдера, например `deepseek-chat`.
   - **Использовать облако по умолчанию для новых чатов** — если включено, при
     создании новой сессии чата будет выбран провайдер `cloud`.
3. Нажать «Проверить подключение». Должна появиться зелёная плашка с коротким
   ответом модели.
4. Нажать «Сохранить».
5. В чате появится переключатель «🔒 Локально / ⚡ Облако».

## Безопасность ключа

- Ключ хранится в БД (`app_settings.cloudProvider.apiKey`) в plaintext.
- Проект предполагается полностью локальным, без внешнего доступа к Postgres.
  Если БД будет открыта в сеть — ключ может утечь. Этот трейд-офф выбран
  осознанно вместо шифрования с master-key, который сам пришлось бы где-то
  хранить.
- В API ключ возвращается замаскированным (`sk-•••••a3f9`). Полный ключ
  никогда не отдаётся клиенту повторно после сохранения.
- При повторном сохранении: если в поле API Key осталась маска или пусто —
  старый ключ в БД сохраняется. Если ввели новый — записывается.
- В логи kb-api ключ не пишется ни в одной форме (ни в headers, ни в body
  запросов, ни в ошибках).
- В git не коммитится: БД не лежит в репозитории.

## Поведение при ошибках

- Нет интернета, 401 (неверный ключ), 403, 429 (rate limit), 5xx (ошибка
  сервера), timeout — ассистент отвечает текстом ошибки на русском и
  показывает кнопку **«Переключиться на локальный ИИ»**.
- Автоматический fallback на локальную модель отключён намеренно: пользователь
  сам решает, отправлять ли следующий запрос на локальную модель или
  переформулировать вопрос для облака.
- При ошибке `no_credentials` кнопка переключения не показывается — нужно
  настроить облако в «Настройках».

Классификация ошибок (`CloudProviderError.code`):

| код             | что значит                                          |
| --------------- | --------------------------------------------------- |
| `no_credentials`| Не задан Base URL, ключ или модель                  |
| `unauthorized`  | 401 или 403 — ключ неверный или просрочен           |
| `rate_limit`    | 429 — провайдер ограничивает запросы                |
| `server_error`  | 4xx (кроме 401/403/429) или 5xx — ошибка провайдера |
| `timeout`       | Превышен таймаут (60 с по умолчанию, 20 с в тесте)  |
| `network`       | DNS, ECONNREFUSED, ENOTFOUND и т.п.                 |

## Ограничения

- Эмбеддинги облачного провайдера игнорируются — в проекте всегда используется
  локальный `qwen3-embedding:0.6b`.
- История чата при отправке в облако обрезается до последних 6 сообщений +
  текущий вопрос (для экономии токенов и приватности). Локальная генерация
  работает без такой обрезки.
- Streaming не реализован — клиент ждёт полного ответа от провайдера. Стрим
  можно добавить позже, не меняя API.
- Контроль над тем, что попадёт в облако, лежит на пользователе: фильтры в
  чате (раздел / документы) позволяют сузить поиск только до открытых
  документов, прежде чем отправить вопрос в облако.
