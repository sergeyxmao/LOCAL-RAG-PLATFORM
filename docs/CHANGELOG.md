# Changelog

## 2026-05-27

- **Cloud chat timeout вынесен в env.** `CLOUD_CHAT_TIMEOUT_MS` (дефолт 180000) — заменяет зашитые в коде 60000 мс, которые обрывали длинные ответы reasoning/pro-моделей посреди абзаца. Прокидывается в `infra/docker-compose.yml` через `kb-api.environment`.
- **HyDE (Hypothetical Document Embeddings) — новый опциональный слой retrieval.** Перед semantic-поиском облачный LLM генерирует гипотетический параграф документа по вопросу пользователя, эмбеддинг считается по нему. Лечит vocabulary mismatch («активный модуль с питанием» ↔ «оборудован канальным источником рабочего напряжения»). По умолчанию выключен. Включается в UI «Настройки → HyDE»: выбор провайдера из `cloudProviders`, опциональная модель, maxTokens/timeoutMs, редактируемый промпт (по умолчанию — универсальный, не привязан к АСУ ТП). BM25 продолжает работать по сырому вопросу. Graceful fallback на любой ошибке. Видимость в чате — бейдж `HyDE: использован (модель, Nмс)` / `HyDE: fallback (причина)`. Подробно: [HYDE_RETRIEVAL.md](HYDE_RETRIEVAL.md).
- API: `GET/PATCH /api/v2/settings/hyde`, `DELETE /api/v2/settings/hyde/prompt`. Структура настроек в `app_settings.hyde`: `{ enabled, providerId, model, maxTokens, timeoutMs, prompt }`. Hyde-метаданные прокидываются через `searchService.hybridSearch → answerService → chatSessionService → метаданные ассистент-сообщения` по тому же пути, что и `reranking`.

- `/ui/consult` получил вкладки `Ответ` / `Источники ответа` в одной рабочей области, кнопку `Найти источники` после исправления клиентского JS, читаемые карточки источников и ручное изменение ширины `Библиотеки документов`.
- `/ui/ingest` больше не показывает восстановленные после обновления страницы локальные файлы как вечное `ожидает`: такие карточки получают статус `выберите заново`, кнопку `Убрать` и очищаются из localStorage после показа.
- Добавлен безопасный сброс тестовой базы: `POST /admin/reset-content` с подтверждением `RESET_LOCAL_RAG_CONTENT` и скрипт `scripts/reset-rag-content.ps1`; очищаются документы, chunks, assets, jobs, query logs, Qdrant points и файлы `data/raw|parsed|assets`, схема и системный раздел сохраняются.
- Усилен классификатор PDF-страниц до `v3`: добавлены признаки содержаний с dotted leaders, табличных строк, схем/чертежей, экранов/HMI, клемм/электрики, сигналов и функциональных блоков.
- Добавлен точечный `POST /documents/:id/rebuild-visual-assets`: можно создать preview/OCR для выбранных страниц PDF без повторного импорта всего документа.
- OCR подключён только как локальный режим через `tesseract` (`ocrMode=off|try|require`), без внешних сервисов и без отправки рабочих документов наружу.
- Добавлен лёгкий visual search: `GET/POST /search/visual` и кнопка `Визуальный поиск` на `/ui/pages-search`, поиск ограничивается визуальными page assets `scheme`, `screen`, `table`, `signals`.
- `/ui/pages-search` получил блок `Создать preview/OCR`: выбор документа, диапазон страниц, переключатель preview и режим OCR.
- Закрыт полный проход по `docs/knowledge-nodes-spec.md`: системный `Без раздела` теперь принудительно работает без `includeChildren`, `/nodes` отдаёт ETag/304, `node_counters` обновляются SQL-триггерами, включена фоновая выборочная сверка payload, а readiness расширен до полного набора проверок.
- Реализован опасный режим `DELETE /nodes/:id?strategy=cascade_documents` с двойным подтверждением `confirm=DELETE_DOCUMENTS_AND_NODE` + точное `confirmName`; `/ui/nodes` по-прежнему удаляет только пустые разделы.
- `/ui/nodes` получил drag-and-drop документов на разделы: без Shift документ переносится в раздел, с Shift добавляется дополнительная привязка.
- `POST /documents/:id/open-local` теперь возвращает Windows helper-контракт `token`, `path`, `helper_url/helperUrl`, а UI пробует отправить его в локальный helper и падает обратно на браузерное открытие.
- Импорт можно перевести в production-режим через `REQUIRE_NODE_IDS_FOR_IMPORT=true`: тогда запросы без выбранного раздела блокируются до записи документа.
- Smoke `scripts/knowledge-nodes-smoke.mjs` расширен до 19 сценариев: ETag/304, `node_counters`, `cascade_documents`, manual sample reconciliation и open-local helper-контракт.
- SQL lexical retrieval теперь применяет те же pre-filter условия, что semantic/Qdrant retrieval: `scope`, `documentId/documentIds`, `nodeId/includeChildren`, `selectedTags`, `assetClass`, `engineeringTopic` и `signalTag`.
- Lexical fallback из PostgreSQL теперь возвращает `node_ids`, `node_scope_ids`, `primary_node_id`, `node_paths` и `payload_version`, включая неявный системный раздел `Без раздела` для документов без явных ссылок.
- Qdrant provider автоматически создаёт payload indexes для полей разделов, тегов, типа источника и инженерных признаков; `GET /admin/qdrant-status` показывает список проиндексированных payload-полей.
- Добавлен `/ui/state` для сохранения и восстановления выбранного рабочего раздела UI; `/ui/consult`, `/ui/pages-search`, `/ui/ingest` и `/ui/jobs` читают его при открытии без `nodeId` в URL. Для системного раздела `Без раздела` состояние сохраняется с `includeChildren=false`.
- Smoke `scripts/knowledge-nodes-smoke.mjs` расширен проверкой `/ui/state`; полный прогон прошёл `15/15`, временные `kn-smoke-*` документы и разделы очищены.
- Добавлен live-контроль готовности `knowledge_nodes`: `GET /admin/knowledge-nodes-status` проверяет системный раздел, closure, primary-ссылки, Qdrant payload indexes, совпадение Qdrant с indexed PostgreSQL, активные задачи и UI-state.
- `/ui/nodes` показывает блок `Готовность разделов базы` с процентом и отдельными проверками; текущая live-проверка после smoke показывает `100%`.

## 2026-04-27
- Добавлена первая версия страницы `/ui/nodes` для управления деревом разделов базы знаний.
- Страница показывает дерево, счётчики, документы выбранного раздела, ссылки в scoped `/ui/consult`, `/ui/ingest`, `/ui/jobs`, создание пользовательских разделов, редактирование, перемещение и ручную синхронизацию payload раздела.
- В `/ui/nodes` добавлена массовая привязка документов к выбранному разделу через `POST /documents/bulk-link`: список до 100 документов, фильтр по названию/пути/тегам, режим `Добавить раздел` или `Заменить разделы`, ограничение до 25 выбранных документов за один раз.
- `/ui/ingest` получил множественный выбор разделов перед загрузкой: рабочий раздел остаётся primary, дополнительные разделы отмечаются чекбоксами и уходят в `nodeIds` вместе с upload/ingest-запросами.
- `/ui/consult` показывает разделы в карточках документов: основной раздел отдельным бейджем и дополнительные разделы через строку `Также в`; источники поиска показывают `node_paths`, если они есть в payload.
- В `/ui/nodes` добавлено безопасное удаление только пустых пользовательских разделов: сначала проверяются потомки/документы/страницы, затем требуется ввести точное название раздела; документы через этот UI не удаляются.
- Таблица `Документы выбранного раздела` в `/ui/nodes` теперь показывает прямые привязки документа к разделам и отмечает основной раздел.
- В таблице документов выбранного раздела добавлен выбор строк и кнопка `Убрать из текущего раздела` для безопасной массовой отвязки через `POST /documents/bulk-unlink`; для системного `Без раздела` кнопка отключена.
- Добавлен безопасный импорт дерева разделов: `POST /nodes/import?dryRun=true` проверяет JSON без записи, обычный импорт создаёт только отсутствующие пользовательские разделы; `/ui/nodes` получил поле вставки JSON из экспорта.
- `PATCH /nodes/:id`, `POST /nodes/:id/move` и `DELETE /nodes/:id` теперь автоматически пересчитывают Qdrant payload затронутых документов (`node_paths`, `node_scope_ids`, `primary_node_id`) и возвращают краткий `sync`-статус; `/ui/nodes` показывает этот результат после сохранения, перемещения и удаления.
- Добавлен scoped API `GET /tags?nodeId=...&includeChildren=true`; окно `#` в `/ui/consult` теперь берёт список тегов текущего раздела из backend, а не только из уже отрисованных карточек документов.
- `/search`, `/search/pages`, `/ask` и `/ask/pages` теперь принимают `selectedTags` и фильтруют semantic + lexical retrieval по `documents.categories`; `/ui/consult` передаёт выбранные `#теги` в payload поиска и ответа.
- Hybrid search теперь мягко деградирует до lexical search из PostgreSQL, если semantic search/Qdrant временно недоступен; причина сохраняется в `debug.semantic_error`.
- Добавлены безопасные recovery-инструменты для Qdrant: `GET /admin/qdrant-status`, dry-run/confirm endpoint `POST /admin/rebuild-qdrant` и скрипт `scripts/recover-qdrant-collection.ps1`, который переносит повреждённую коллекцию в backup без удаления.
- В `/ui/consult` уточнён UX тегов: кнопка называется `Теги #`, выбранные теги видны в окне до применения, а действие `Найти источники` вынесено рядом с `Ответить`.
- Lexical search теперь учитывает смешанную раскладку в технических кодах: запрос вроде `RAMPТ` с русской `Т` автоматически проверяется также как латинский `RAMPT`.
- Редактирование тегов документа больше не падает при недоступном Qdrant: категории сохраняются в PostgreSQL и `document_chunks`, а payload Qdrant обновляется best-effort с предупреждением в UI.
- В основную навигацию добавлен пункт `Разделы базы`.
- Добавлена нормализация ошибочного тега `met-o` в `metso` при вводе, сохранении, списке тегов и фильтрации поиска.
- Для восстановления Qdrant увеличен допустимый `batchSize` пересборки до 250, чтобы не раздувать коллекцию множеством мелких 32 МБ сегментов.
- Embedding provider теперь поддерживает `EMBEDDING_BATCH_SIZE` и по умолчанию отправляет в Ollama пачки по 8 текстов вместо 2, чтобы ускорить rebuild Qdrant на локальной машине.
- Для слабого ноутбука добавлен параметр `EMBEDDING_MAX_INPUT_CHARS`; дефолт уменьшен до 400 символов на embedding-вход, чтобы восстановление Qdrant не зависало на длинных chunk-ах.
- В `/ui/jobs` добавлена панель состояния Qdrant/PostgreSQL и последней синхронизации, чтобы проверять восстановление базы без ручного JSON-запроса.
- `GET /admin/qdrant-status` теперь отдельно показывает все записи PostgreSQL и записи только по документам `indexed`, чтобы число точек Qdrant не путалось со старыми failed/cancelled импортами.
- `POST /admin/rebuild-qdrant` по умолчанию пересобирает только документы `indexed`; для редкой полной пересборки можно явно передать `documentStatus=all`.
- `/ask` теперь явно сообщает, что источники не найдены именно в выбранном разделе, и передаёт `node_paths` в контекст источников для ответа.
- Добавлен регрессионный smoke-тест `scripts/knowledge-nodes-smoke.mjs`: создаёт временные разделы и маленькие текстовые документы, проверяет 15 сценариев из спецификации `knowledge_nodes`, затем удаляет только свои `kn-smoke-*` данные.
- Исправлено удаление раздела со стратегией `move_to_parent`: target node теперь передаётся в SQL как `uuid`, а ссылки истории задач `job_node_links` больше не блокируют удаление пустого пользовательского раздела.
- Уточнены UX-тексты для scoped-фильтров: `/ui/consult` теперь явно различает фильтр по `#тегам` и ручной выбор документов, `/ui/jobs` показывает последнюю операцию payload без ощущения, что `0 точек` означает поломку Qdrant, а `/ui/nodes` понятнее объясняет синхронизацию пустых разделов.
- `/ui/nodes` теперь сразу показывает, что системный раздел `Без раздела` нельзя редактировать, перемещать, удалять или вручную пополнять; массовая привязка к нему отключена.
