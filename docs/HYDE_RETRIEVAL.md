# HyDE — Hypothetical Document Embeddings

## Что это и зачем

HyDE — слой поиска, который **перед** semantic-этапом превращает вопрос пользователя в гипотетический параграф документа и эмбеддит уже его, а не сырой вопрос. Лечит «промах слов» (vocabulary mismatch): когда пользователь говорит человеческим языком («активный модуль с питанием датчика»), а в техдоке написано инженерным («оборудован канальным источником рабочего напряжения для датчика-преобразователя»).

В нашем пайплайне HyDE влияет **только на semantic-эмбеддинг запроса**. BM25-поиск (Postgres lexical) по-прежнему идёт по сырому вопросу — он про точные термины, и гипотетический параграф их размоет.

```
вопрос пользователя ──┬──► HyDE (cloud LLM) ──► гипотетический параграф ──► эмбеддер ──► Qdrant
                      │
                      └──────────────────────────────► BM25 (Postgres)
                                                              │
                                                              ▼
                                                     RRF (semantic + bm25)
                                                              │
                                                              ▼
                                                          reranker
                                                              │
                                                              ▼
                                                         финальный top-K
```

## Когда включать

**Включайте**, если:
- Вопросы у вас расплывчатые, без точных терминов из техдока («какой модуль сам подаёт питание на датчик?»).
- Пользователь — не автор документа, формулирует «своими словами».
- Поиск возвращает релевантные источники, но не самые точные.

**Не включайте** (или выключайте), если:
- Вопросы конкретные, с точными артикулами и номерами («сколько весит ACU», «характеристики AII8C»).
- Скорость важнее точности — HyDE добавляет 2-5 секунд на каждый запрос.
- Не настроен быстрый облачный провайдер — на reasoning-моделях HyDE убьёт latency.

По умолчанию HyDE **выключен**. Включается осознанно через UI «Настройки → HyDE».

## Настройки

UI: «Настройки → HyDE» (вкладка «Поиск»). Все поля сохраняются в Postgres `app_settings.hyde`.

| Поле | Что делает | Дефолт |
|---|---|---|
| `enabled` | Включает/выключает HyDE | `false` |
| `providerId` | Какой облачный провайдер использовать (из «Настройки → Облачные провайдеры») | пусто |
| `model` | Перебивает модель провайдера. Оставьте пустым — возьмётся модель из настроек провайдера | пусто |
| `maxTokens` | Длина гипотетического параграфа | `400` |
| `timeoutMs` | Таймаут на HyDE-вызов. По истечении — fallback на сырой вопрос | `15000` |
| `prompt` | Системный промпт для HyDE-генерации | универсальный (см. ниже) |

**Промпт** — отдельная редактируемая в UI настройка. По умолчанию — доменно-агностичный текст:

```
Ты помогаешь поисковой системе по технической документации.
Получив вопрос пользователя, сгенерируй ОДИН развёрнутый абзац (200-400 слов) в стиле документации того предмета, о котором задан вопрос — как если бы это был фрагмент реального документа, где даётся ответ на этот вопрос.
Используй терминологию и стиль, характерные для соответствующей области (если вопрос про оборудование — технические параметры и обозначения; если про процессы — этапы и роли; если про правила — формулировки нормативного типа; и т.д.). Старайся имитировать, как мог бы быть написан ответ в реальном документе.
Не отвечай пользователю напрямую и не давай советов — просто напиши гипотетический параграф документа. Без преамбулы, без оговорок, без markdown — только сам параграф сплошным текстом.
```

Вы можете заточить его под свой домен — добавить специфическую терминологию, обозначения, стиль. Кнопка «Сбросить промпт к универсальному» возвращает дефолт.

## Какую модель брать

HyDE — синхронный шаг перед поиском, поэтому скорость критична. Рекомендации:

- **Хорошо:** `deepseek-v4-flash`, `deepseek-chat`, GPT-4o-mini, Gemini Flash, любая «turbo/flash/mini»-вариация.
- **Плохо:** reasoning-модели (deepseek-pro, o1, Claude Sonnet 4.6 thinking) — добавят 20+ секунд.

В UI выбираете один из уже настроенных в «Облачных провайдерах». Если хотите другую модель этого же провайдера — пишите её имя в поле «Модель».

## Видимость в чате

Под каждым ответом ИИ появляется бейдж:
- `HyDE: использован · <модель> · <Nмс>` — синий, успех.
- `HyDE: fallback (короткий ответ)` — оранжевый, модель вернула <50 символов.
- `HyDE: fallback (ошибка)` — оранжевый, ошибка/таймаут. Hover для деталей.
- `HyDE: fallback (провайдер не настроен)` — оранжевый, в настройках не выбран `providerId`.
- `HyDE: fallback (нет модели)` — оранжевый, ни в HyDE, ни в провайдере не задана модель.
- `HyDE: fallback (пустой промпт)` — оранжевый, очищенный промпт.
- (отсутствует) — HyDE выключен (`enabled: false`).

Это требование владельца: всегда видеть, какой слой сработал, по аналогии с бейджем reranking.

## API

```
GET    /api/v2/settings/hyde          → текущие настройки + дефолтный промпт
PATCH  /api/v2/settings/hyde          → обновить (см. JSON-схему в settingsApi.js)
DELETE /api/v2/settings/hyde/prompt   → сбросить только промпт к дефолту
```

PATCH-схема:
- `enabled` — boolean
- `providerId` — string ≤ 128
- `model` — string ≤ 256
- `maxTokens` — int 50-2000
- `timeoutMs` — int 2000-60000
- `prompt` — string ≤ 8000

Все поля опциональны.

## Graceful fallback

HyDE никогда не должен ломать поиск. На любой ошибке `searchService` ловит исключение, логирует warning и идёт с сырым query. Возможные причины fallback:
- `disabled` — HyDE выключен в настройках.
- `no_provider` — `providerId` пуст, или провайдер удалён, или у него нет ключа.
- `no_model` — ни в HyDE, ни в провайдере не задано имя модели.
- `no_prompt` — поле `prompt` пустое.
- `short_response` — модель вернула < 50 символов (вряд ли будет полезно для эмбеддера).
- `error` — таймаут, сетевая ошибка, ошибка облака.

Все случаи видны в логах kb-api и в бейдже под ответом.

## Что HyDE НЕ делает

- Не заменяет финальный ответ пользователю — этим занимается основной чат-провайдер с системным промптом.
- Не влияет на BM25-поиск.
- Не сохраняется как «ответ» нигде. Гипотетический параграф используется только для вычисления одного эмбеддинга и тут же забывается.
- Не отправляется пользователю.

## Связь с другими слоями

- **Эмбеддер** ([docs/GIGACHAT_EMBEDDING.md](GIGACHAT_EMBEDDING.md)) — HyDE-параграф проходит через тот же эмбеддер, что и при индексации (Sber GigaChat). Поэтому HyDE особенно эффективен на эмбеддерах с хорошим semantic-сходством по русскому языку.
- **Reranker** ([docs/RERANKER_SERVICE.md](RERANKER_SERVICE.md)) — работает после HyDE+RRF, переоценивает финальный пул кандидатов.
- **Системный промпт** ([docs/CLOUD_PROVIDER.md](CLOUD_PROVIDER.md)) — отдельная настройка, для финального ответа. HyDE-промпт от него независим.
