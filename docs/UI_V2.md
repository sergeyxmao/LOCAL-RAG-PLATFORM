# UI v2 — обновлённый интерфейс

## Что делает

Современный интерфейс для работы с локальной RAG-платформой. Заменяет 5 разрозненных
служебных страниц на 3 крупных раздела: **Чат**, **База знаний**, **Настройки**.
Старый UI остаётся доступен по прежним путям (`/ui/consult`, `/ui/ingest`, `/ui/nodes`,
`/ui/jobs`, `/ui/pages-search`) и может использоваться как откат, пока новый UI ещё
обкатывается.

К итерации 3 готовы все три раздела: «Чат», «База знаний», «Настройки». Также
добавлен опциональный облачный провайдер (см. `docs/CLOUD_PROVIDER.md`) и старый
UI скрыт за `?admin=1`.

## Расположение в коде

- `apps/kb-api/src/routes/uiV2.js` — общий layout, навигация, переключатель темы.
- `apps/kb-api/src/routes/uiV2Chat.js` — страница чата (HTML + CSS + JS).
- `apps/kb-api/src/routes/uiV2Knowledge.js` — страница «База знаний».
- `apps/kb-api/src/routes/uiV2Settings.js` — страница «Настройки».
- `apps/kb-api/src/routes/chatSessions.js` — REST API сессий и сообщений.
- `apps/kb-api/src/routes/settingsApi.js` — REST API настроек `/api/v2/settings/*`.
- `apps/kb-api/src/routes/adminFlag.js` — preHandler с проверкой `?admin=1` /
  cookie `admin_mode` для всех старых UI-маршрутов.
- `apps/kb-api/src/services/chatSessionService.js` — бизнес-логика сессий,
  выбирает между `answerService`/`searchService` (локально) и
  `cloudChatProvider` (облако).
- `apps/kb-api/src/services/appSettingsService.js` — CRUD над `app_settings`,
  маскирование API-ключа.
- `apps/kb-api/src/providers/cloudChatProvider.js` — универсальный
  OpenAI-совместимый клиент (без SDK).

Использует существующие модули без изменения их сигнатур:

- `answerService` (`/api/v2/chat/...` режим `answer`, провайдер `local`).
- `searchService` (`/api/v2/chat/...` режим `pages`, всегда локально).
- `GET /nodes`, `GET /nodes/counts`, `GET /documents` — для дерева, документов и
  счётчиков на обеих страницах.
- `POST /documents/upload`, `POST /documents/ingest-folder-async` — для загрузки
  файлов и серверных папок со страницы «База знаний».
- `GET /jobs`, `POST /jobs/:id/cancel` — задачи импорта.
- `GET /tags` — автодополнение тегов в редакторе.
- `POST /nodes`, `PATCH /nodes/:id`, `DELETE /nodes/:id?strategy=...` — операции
  с деревом со страницы «База знаний».
- `PATCH /documents/:id`, `PATCH /documents/:id/nodes`, `DELETE /documents/:id`,
  `POST /documents/bulk-link` — операции с документами.
- `POST /admin/rebuild-qdrant`, `POST /admin/reset-content` — обслуживание со
  страницы «Настройки».

## Как использовать

### Страница «База знаний» (`/ui/v2/knowledge`)

Готова с итерации 2. Заменяет связку `/ui/ingest` + `/ui/jobs` + `/ui/nodes` в
одном экране. Сама `/ui/nodes` остаётся доступной как расширенный редактор
дерева — ссылка на неё есть внизу левой колонки.

1. **Левая колонка — дерево разделов.** Кнопка «+ Раздел» сверху создаёт новый
   корневой раздел. По наведению на узел появляется кнопка «⋯» с пунктами
   «Переименовать», «Создать вложенный», «Удалить». Удаление раздела с
   документами автоматически использует `strategy=move_to_parent` (или
   `move_to_unsorted`, если родителя нет) — документы не теряются. Удаление
   раздела с потомками заблокировано: для этого используйте `/ui/nodes`.
2. **Шапка** — заголовок «База знаний» и сводка по выбранному узлу (или по всей
   базе, если узел не выбран): `N документов · M страниц · K чанков`.
3. **Зона «Загрузка».**
   - Перетащите файлы или папку в drop-zone — каждый файл уйдёт через
     `POST /documents/upload` с указанием выбранного целевого раздела.
   - «Выбрать файлы» — стандартный диалог выбора нескольких файлов.
   - «Выбрать папку» — через `<input webkitdirectory>` (поддерживается в
     Chromium/Edge/Firefox).
   - Поле «Путь к локальной папке на сервере» — серверный импорт через
     `POST /documents/ingest-folder-async`. По умолчанию включён «Лёгкий режим»
     (`createVisualAssets=false`) и «Включая вложенные папки» (`recursive=true`).
   - Выпадающий список «Целевой раздел» — узел, в который будут привязаны
     импортированные документы.
4. **Зона «Задачи импорта».** Свёрнута по умолчанию (одна строка `N активных ·
   M завершено`). Раскрывается по кнопке. Polling `GET /jobs?limit=20` — раз в
   3 секунды, пока есть активные задачи, и приостанавливается на скрытой
   вкладке. У каждой активной задачи доступна кнопка «Отменить»
   (`POST /jobs/:id/cancel`).
5. **Зона «Документы».**
   - Таблица: чекбокс · Имя · Страниц · Раздел · Теги · Загружен · Действия.
   - Поле поиска фильтрует уже загруженный список (по названию и пути).
   - Переключатель «Только в этом разделе / Включая вложенные» меняет
     `includeChildren` запроса `GET /documents?nodeId=...`.
   - Действия в строке: открыть исходник (`/documents/:id/original` в новой
     вкладке), переместить в другой раздел (`PATCH /documents/:id/nodes`),
     редактировать теги (модалка), удалить (`DELETE /documents/:id`,
     двойное подтверждение в 3 секунды).
   - Массовый выбор через чекбоксы — появляется панель «Переместить» и
     «Удалить выбранные». Массовое перемещение пробует
     `POST /documents/bulk-link` и фоллбэчит на последовательные
     `PATCH /documents/:id/nodes`, если bulk-link отказал.
6. **Редактор тегов** — модальное окно. Теги документа — это поле
   `documents.categories` (массив строк). Изменения сохраняются через
   `PATCH /documents/:id` с обновлением Qdrant payload. Под полем ввода —
   подсказки из глобального списка тегов (`GET /tags?limit=100`).

### Страница «Настройки» (`/ui/v2/settings`)

Готова с итерации 3. Шесть карточек:

1. **Модели** — read-only. Текущая чат-модель, embedding-модель, базовый URL
   Ollama. Все значения берутся из `config/models.yaml` и env. Редактирование
   через UI отключено намеренно: чтобы не было рассинхрона между UI и
   контейнером.
2. **Облачный ИИ** — настройка любого OpenAI-совместимого провайдера. Подробно
   описано в `docs/CLOUD_PROVIDER.md`. Поля: название, Base URL, API Key,
   модель, флаг «использовать по умолчанию». Кнопки «Проверить подключение»
   (короткий запрос «Скажи слово ОК») и «Сохранить».
3. **Сервисы** — кнопкой «Обновить» опрашиваются Postgres, Qdrant, Ollama и
   kb-api через `GET /api/v2/settings/services`. Зелёная точка = онлайн,
   красная = недоступен.
4. **Поиск** — read-only сводка из `config/retrieval.yaml`.
5. **Внешний вид** — тема по умолчанию (`dark` / `light` / `system`).
   Сохраняется в `app_settings.theme`. Применяется к пользователям, у которых
   нет личного выбора в `localStorage.localrag.theme`.
6. **Обслуживание** — «Пересобрать Qdrant» (через `POST /admin/rebuild-qdrant`
   с `confirm=REBUILD_QDRANT`), «Сброс содержимого» (через
   `POST /admin/reset-content` с `confirm=RESET_LOCAL_RAG_CONTENT` и
   подтверждением словом `УДАЛИТЬ`). Бэкап БД пока через PowerShell-скрипты —
   указано хинтом со ссылкой на `docs/BACKUP_RESTORE.md`.

### Переключатель «🔒 Локально / ⚡ Облако» в чате

Появился с итерации 3. Сидит в шапке `/ui/v2/chat` рядом с «Ответ ИИ / Найти
страницы». Поведение:

- Если облако не настроено — кнопка «Облако» серая, тултип «Настройте облако в
  разделе Настройки».
- Если в Настройках включено «Использовать по умолчанию» — новая сессия
  создаётся сразу с `provider='cloud'`.
- При выборе «Облако» под шапкой появляется светло-янтарная плашка «Фрагменты
  документов уйдут во внешний API (имя провайдера)».
- Выбор сохраняется в `chat_sessions.provider` через `PATCH /api/v2/chat/sessions/:id`.
- Под ответом ассистента видна мелкая строка: для облака — `deepseek-chat ·
  1240 in / 320 out · 850 мс`, для локалки — `qwen3:4b · 4530 мс`.
- При ошибке облака ответ приходит с красной плашкой и кнопкой «Переключиться
  на локальный ИИ» — клик переключает сессию на `local` и повторяет последний
  пользовательский вопрос.

### Через UI (страница «Чат», `/ui/v2/chat`)

1. Открыть `http://localhost:8787/ui/v2/chat`.
2. В левом сайдбаре выбрать «Новый чат» (или открыть один из прошлых).
3. В шапке выбрать режим:
   - **Ответ ИИ** — модель отвечает по найденным источникам.
   - **Найти страницы** — выдаётся только список страниц документов, без генерации
     ответа.
4. По кнопке «Фильтры» открыть правую панель и выбрать разделы и/или конкретные
   документы. Кнопка «Применить» сохраняет выбор в текущей сессии.
5. Переключатель темы — иконка солнца/луны в шапке. Тема сохраняется в
   `localStorage` (`localrag.theme`).
6. В сайдбаре есть ссылка «Старый интерфейс» — ведёт на `/ui/consult`. Аналогично,
   в шапках старого UI добавлена ссылка «Новый дизайн (β)», ведущая обратно сюда.

### Через API

- `GET /api/v2/chat/sessions` — список сессий (по `updated_at DESC`, лимит 50).
- `POST /api/v2/chat/sessions` — создать сессию. Тело: `{ title?, mode?, filters? }`.
- `GET /api/v2/chat/sessions/:id` — детали сессии + все сообщения.
- `PATCH /api/v2/chat/sessions/:id` — обновить `title`, `mode` или `filters`.
- `DELETE /api/v2/chat/sessions/:id` — удалить (каскадом удалятся сообщения).
- `POST /api/v2/chat/sessions/:id/messages` — добавить сообщение пользователя,
  получить ответ ассистента. Тело: `{ content }`. Ответ:
  `{ userMessage, assistantMessage }`.

Полный список и примеры curl — в `docs/API_SPEC.md`.

## Технические детали

- Ванильный HTML/JS, без сборки и фреймворков. Это сознательное решение из-за
  слабого ноутбука и ограниченного диска `C:`. План миграции на полноценный SPA
  упомянут в `docs/ROADMAP.md`.
- Тёмная тема — по умолчанию. Переключение через `localStorage.localrag.theme`.
  Чтобы избежать «мигания» светлой темы при загрузке, тема ставится inline-скриптом
  в `<head>` до отрисовки body.
- Шрифты: `Inter` (400, 500, 600) для интерфейса, `JetBrains Mono` для тегов,
  путей, идентификаторов и числовых значений. Если Google Fonts недоступны —
  fallback на `system-ui` и `monospace`.
- Иконки — inline-SVG из набора Lucide, чтобы не подключать всю библиотеку.
- История чатов и фильтры хранятся в PostgreSQL (таблицы `chat_sessions` и
  `chat_messages`) и переживают перезапуск контейнеров.
- Фильтры:
  - `filters.nodeIds` — массив выбранных узлов. На сервере в эту итерацию
    `answerService`/`searchService` принимают только один `nodeId`, поэтому
    передаётся первый из массива с `includeChildren = true`.
  - `filters.documentIds` — массив документов, передаётся как есть.
- Источники из ответа сохраняются в `chat_messages.sources` (JSONB). В метаданных
  сообщения ассистента (`chat_messages.metadata`) лежат `mode` (например,
  `llm`, `fallback-empty`, `error`), `durationMs` и `searchMode`.
- Поток ответа — синхронный (`POST /api/v2/chat/sessions/:id/messages` ждёт
  завершения). Стриминг не добавлялся, потому что `OllamaChatProvider.generate`
  возвращает полный ответ. Когда добавится streaming в провайдер — UI допилим.

## Ограничения и риски

- Ванильный JS — при росте сложности код станет тяжёлым. План миграции на SPA —
  в `docs/ROADMAP.md`.
- Дерево разделов и список документов загружаются одним запросом каждый. При
  очень большом дереве (>1000 узлов) возможны задержки на слабом железе —
  рассмотреть lazy-loading в будущих итерациях.
- Множественный выбор разделов на странице чата: на сервере используется только
  первый `nodeId` с `includeChildren = true`. Точное пересечение поддерева
  потребует расширения `searchService.hybridSearch` (отложено).
- При недоступности Ollama чат показывает осмысленное сообщение через
  `chatSessionService.describeError(...)` и не падает.
- При пустых результатах — честный `fallback-empty` от `answerService`, без
  выдумывания.
- Загрузка через браузер ограничена лимитами Fastify multipart (по умолчанию
  ~100 МБ на файл). Для больших папок используйте импорт по серверному пути.
- Удаление раздела с вложенными разделами в новом UI заблокировано — для этого
  оставлен расширенный редактор `/ui/nodes`. Cascade-удаление с документами
  (`?strategy=cascade_documents`) требует ввода точного имени и не вынесено в
  новый UI намеренно, чтобы избежать случайных потерь данных.
- Загрузка через drop-zone отправляет файлы по одному (multipart с
  `XMLHttpRequest`). При очень больших партиях имеет смысл использовать
  серверный импорт через `POST /documents/ingest-folder-async`.
- **API-ключ облачного провайдера хранится в `app_settings.cloudProvider.apiKey`
  в plaintext.** Проект полностью локальный, без внешнего доступа к Postgres —
  трейд-офф выбран осознанно. Подробности и риски — в `docs/CLOUD_PROVIDER.md`.
- **Старый UI скрыт за `?admin=1`.** Открытие `/ui/consult`, `/ui/ingest`,
  `/ui/jobs`, `/ui/pages-search`, `/ui/nodes` без флага возвращает 404 с
  HTML-страницей и ссылкой на новый UI. Cookie `admin_mode=1` (TTL 1 час)
  ставится при заходе с `?admin=1` и работает для последующих переходов.
- Авто-fallback с облака на локальную модель отключён намеренно — при ошибке
  пользователь сам решает, что делать дальше.
- В режиме «Облако» история чата при отправке обрезается до 6 последних
  сообщений + текущий вопрос (экономия токенов и приватность). Локальные
  сессии работают без обрезки.
