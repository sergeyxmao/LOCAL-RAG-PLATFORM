# Контекстное обогащение чанков (Contextual Retrieval) — Слой 2

## Что это и зачем

При импорте текстового документа (docx/txt/md) каждый фрагмент (чанк) **перед индексацией** обогащается облачным LLM: к нему добавляется краткий **контекст** («где фрагмент в документе и о чём он»), набор **тегов** и краткое **описание** (summary).

Проблема, которую это лечит: фрагмент «Неисправен ИБП Smart UPS RT 1000» сам по себе не знает, что это запись от 03.08.2021 по КС-3 Правдинского про последствия грозы. Голый фрагмент плохо находится semantic-поиском (vocabulary mismatch + потеря контекста). Обогащённый фрагмент — `Document: Вахта\nКонтекст: Запись вахтового журнала от 03.08.2021, КС-3 Правдинского: последствия грозы, замена ИБП в шкафу ИВК\n\nНеисправен ИБП Smart UPS RT 1000…` — находится и semantic, и BM25.

Это **Слой 2** апгрейда качества текстовой базы. **Слой 1** — структурный чанкинг (см. [INGESTION_PIPELINE.md](INGESTION_PIPELINE.md)) — режет текст мельче и по смысловым границам. Архитектура слоя 2 повторяет HyDE: настройки и промпты в БД, редактируются в UI, граница graceful fallback, бейдж видимости.

## Контракт

Модель возвращает строго JSON:

```json
{ "context": "1–2 предложения: где фрагмент и о чём", "tags": ["#тег1", "#тег2"], "summary": "краткое описание ≤300 символов" }
```

- **`context`** — идёт в индекс (эмбеддинг + BM25) вместе с текстом через `text_with_context`.
- **`tags`** (≤10, каждый с `#`), **`summary`** (≤300 символов) — **только метаданные** для отображения и фильтров. В вектор и BM25 **не идут** (подтверждено опытом FOHOW: размывают вектор и шумят в BM25).

**Текст чанка НЕ переписывается.** Оригинал хранится дословно в `payload.text` и в колонке `document_chunks.text`. Факты, серийные номера, коды, адреса, теги — без искажений.

Формат строки, уходящей в поиск (`text_with_context`):

```
Document: <Заголовок>
Контекст: <context>

<дословный текст чанка>
```

Без обогащения (fallback) — как раньше: `Document: <Заголовок>\n\n<текст>`.

## Настройки

UI: «Настройки → Поиск → Контекстное обогащение чанков». Все поля сохраняются в Postgres `app_settings.contextual_enrichment`.

| Поле | Что делает | Когда срабатывает | Дефолт |
|---|---|---|---|
| `enabled` | Включает/выключает обогащение | при импорте/переимпорте текстового документа | `false` |
| `providerId` | Облачный провайдер (из «Облачные провайдеры») | — | пусто |
| `model` | Перебивает модель провайдера. В UI поле «Модель для обогащения» — input со списком-подсказкой быстрых flash/turbo-моделей (`deepseek-v4-flash`, `deepseek-chat`, `gemini-2.5-flash`, `gpt-4o-mini`, `qwen-turbo`); можно выбрать из списка или вписать свою. Пусто — берётся модель провайдера. | при импорте | пусто |
| `maxTokens` | Длина ответа модели на фрагмент | при каждом вызове | `1500` |
| `timeoutMs` | Таймаут на вызов; по истечении — fallback | при каждом вызове | `30000` |
| `contextPrompt` | Промпт генерации **контекста** | при импорте | универсальный (см. ниже) |
| `metaPrompt` | Промпт генерации **тегов + описания** | при импорте | универсальный (см. ниже) |

Старт-параметры вызова (по образцу FOHOW): `temperature 0.1`, `maxTokens 1500`, таймаут 30 c, 2 retry (1 c / 3 c). На каждый фрагмент — **один** вызов облачной модели, который возвращает весь JSON-контракт `{context, tags, summary}`.

### Глобальный мастер-выключатель

`config/ingestion.yaml`:

```yaml
contextual_enrichment:
  enabled: true   # глобально разрешает фичу; per-instance тумблер — в UI (по умолчанию off)
```

Обогащение работает, только если мастер-флаг `true` **и** в UI включён `enabled`. Поставьте мастер-флаг в `false`, чтобы выключить фичу глобально на всём инстансе.

### Три промпта системы — не путать

В системе три редактируемых промпта, у каждого своя роль и момент срабатывания (в UI у каждого есть подсказка «?»):

- **HyDE** ([HYDE_RETRIEVAL.md](HYDE_RETRIEVAL.md)) — срабатывает **при вопросе** пользователя, переписывает запрос для поиска.
- **Промпт контекста** (`contextPrompt`) — срабатывает **при импорте** документа, добавляет контекст к фрагментам (идёт в поиск).
- **Промпт тегов/описания** (`metaPrompt`) — срабатывает **при импорте**, генерирует теги и краткое описание (метаданные, в поиск не идут).

### Дефолтные промпты (доменно-агностичные, редактируются в UI)

`contextPrompt`:

```
Ты помогаешь поисковой системе индексировать документы.
Дай краткий контекст (1–2 предложения): где в документе находится приведённый фрагмент и о чём он.
Если во фрагменте есть точные обозначения, коды, идентификаторы, номера, даты, серийные номера, адреса — приведи их в контексте ДОСЛОВНО, не искажая и не сокращая.
Не пересказывай весь документ и не выдумывай деталей, которых нет во фрагменте или общем содержании.
Пиши на языке документа. Это значение пойдёт в поле "context".
```

`metaPrompt`:

```
Дополнительно сгенерируй для этого же фрагмента метаданные:
"tags" — массив коротких тегов по ключевым понятиям фрагмента, каждый с символом «#», не более 10 штук;
"summary" — краткое описание фрагмента не длиннее 300 символов, на языке документа, без вымысла.
Эти значения пойдут в поля "tags" и "summary" и НЕ участвуют в поиске — только для отображения и фильтров.
```

В промпт-обёртку, помимо системных промптов, передаётся: заголовок документа, общее содержание (первые ~8000 символов очищенного текста) и текст фрагмента. У каждого промпта в UI — кнопка «Сбросить к универсальному».

## Как включить

1. Настройте облачного провайдера в «Настройки → Облачные провайдеры» (рекомендуется быстрая flash/turbo-модель).
2. «Настройки → Поиск → Контекстное обогащение чанков»: включите тумблер, выберите провайдера, при желании отредактируйте промпты.
3. **Переимпортируйте** документ (force re-import). Обогащение применяется только при новом импорте/переимпорте.

## Видимость в UI

- Под ответом в чате — бейдж `фрагменты обогащены · N/M` (синий), по аналогии с бейджами HyDE/reranking. Показывает, сколько из найденных фрагментов несут контекст.
- В карточке источника (компактный список): значок `✦` у обогащённых фрагментов; в подсказке (`title`) — `Контекст:` и `Описание:`.

## Парсинг JSON с авто-ремонтом

Паттерн FOHOW, реализован в `parseEnrichmentJson`:

1. Снять markdown-fences (` ```json … ``` `).
2. `JSON.parse` как есть.
3. При ошибке — выдрать первый `{...}` балансировкой скобок.
4. Авто-ремонт типовых косяков: хвостовые запятые, недозакрытые `}`/`]`.
5. При полной неудаче — `null` → fallback (чанк индексируется без обогащения). Импорт **не падает**.

## Graceful fallback (обязателен)

Обогащение никогда не ломает импорт. Если что-то пошло не так — чанк индексируется как раньше (без контекста), причина логируется через `request.log`/`app.log`. Возможные причины:

- `disabled_global` — выключен мастер-флаг в `ingestion.yaml`.
- `disabled` — выключен тумблер в UI.
- `no_provider` — провайдер не выбран/удалён/без ключа.
- `no_model` — модель не задана ни в обогащении, ни у провайдера.
- `no_prompt` — оба промпта пусты.
- `error` — таймаут, сетевая ошибка, ошибка облака, неразбираемый JSON (после retry).

## Изменения в БД

Неразрушающий идемпотентный DDL в `ensureRuntimeSchema`:

```sql
ALTER TABLE document_chunks ADD COLUMN IF NOT EXISTS chunk_context TEXT;
ALTER TABLE document_chunks ADD COLUMN IF NOT EXISTS chunk_tags JSONB;
ALTER TABLE document_chunks ADD COLUMN IF NOT EXISTS chunk_summary TEXT;
```

Существующие данные не трогаются. Лексический полнотекст считает `to_tsvector` на лету из `text_with_context`, поэтому контекст автоматически попадает в BM25 — материализованной `tsvector`-колонки нет, отдельный DDL не нужен.

## Эффект на базу

- Размерность эмбеддингов и коллекция Qdrant **не меняются**. Старые чанки (без контекста) и новые сосуществуют, вектора сравнимы — **переэмбеддинг всей базы не нужен**.
- Оба слоя — **только при новом импорте и переимпорте**. Чтобы применить к `Вахта.docx` — переимпортировать.
- **PDF-документы не затрагиваются** ни Слоем 1, ни Слоем 2 (PDF-путь — постраничные asset-чанки).
- CSV/XLSX используют предсобранные построчные чанки и обогащением не покрываются.

## Ограничения и риски

- **Стоимость:** +1 LLM-вызов на каждый фрагмент при импорте. На большом документе это десятки/сотни вызовов — учитывайте лимиты и оплату провайдера.
- **Приватность:** как и HyDE, тексты фрагментов уходят в облако выбранного провайдера. Не включайте для конфиденциальных документов, если это недопустимо.
- **Скорость импорта:** обогащение синхронно на каждый чанк — импорт становится заметно дольше. Рекомендуется быстрая модель.

## Что обогащение НЕ делает

- Не переписывает текст чанка — только поля-обёртки.
- Не отправляет теги/summary в поиск.
- Не меняет PDF-путь и уже проиндексированные чанки (до переимпорта).
