# Roadmap

Цель проекта: локальный консультант по рабочим документам АСУ ТП.

## Сейчас готово

- Локальная инфраструктура: Docker, Open WebUI, Ollama, PostgreSQL, Qdrant, `kb-api`.
- Индексация файлов из `data/raw`: `.txt`, `.md`, `.pdf`, `.docx`, `.csv`, `.xlsx`, `.xls`.
- Поиск: semantic + lexical + reranking.
- Ответы по источникам: `/ask`, `/ask/pages`, fallback-ответ при слабой локальной модели.
- PDF page-level слой:
  - извлечение текста страниц;
  - PNG-preview страниц;
  - lazy preview для страниц без заранее созданной картинки;
  - точечное создание preview/OCR для выбранных страниц после лёгкого импорта;
  - `document_assets` в PostgreSQL;
  - поиск по PDF-страницам.
- Классификация страниц:
  - `title`
  - `contents`
  - `changelog`
  - `legal`
  - `signals`
  - `table`
  - `scheme`
  - `screen`
  - `text`
- Инженерные признаки:
  - `engineeringTopics`
  - `signalTags`
  - `confidence`
- Фильтры:
  - по документу;
  - по тегам документа `documents.categories`;
  - по типу страницы;
  - по инженерной теме;
  - по точному тегу/сигналу.
- Браузерные страницы:
  - `/ui/consult` — основной режим вопросов по базе;
  - `/ui/ingest` — импорт файлов и папок;
  - `/ui/nodes` — управление деревом разделов базы знаний;
  - `/ui/pages-search` — поиск по страницам PDF;
  - `/ui/jobs` — статусы задач импорта.
- Фоновый импорт:
  - `/documents/ingest-file-async`
  - `/documents/ingest-folder-async`
- Защита от дублей: повторный импорт уже индексированного файла пропускается, если не передан `force: true`.
- Очистка дублей через UI/API.
- Управление задачами:
  - `Остановить`
  - `Повторить`
- Честный режим ответа без источников:
  - `fallback-empty`
- Первый безопасный слой разделов базы знаний:
  - таблицы `knowledge_nodes`, `knowledge_node_closure`, `document_node_links`, `job_node_links`, `node_counters`;
  - системный раздел `Без раздела`;
  - API `/nodes` для дерева, счётчиков, create/rename/move/delete;
  - защита системного раздела от изменения и удаления;
  - API привязки документов к разделам;
  - ручной пересчёт Qdrant payload разделов без пересоздания векторов;
  - auto-sync Qdrant payload для затронутых документов после rename/move/delete раздела;
  - endpoints импорта принимают `nodeIds`/`primaryNodeId` и пишут payload разделов для новых документов;
  - `GET /documents` умеет отдавать список документов выбранного раздела;
  - `GET /tags` умеет отдавать список тегов документов выбранного раздела;
  - `GET /jobs` умеет отдавать задачи выбранного раздела;
  - `POST /admin/reindex-nodes` и `GET /admin/sync-status` дают ручную сверку payload разделов Postgres -> Qdrant перед включением scoped search;
  - `GET /admin/qdrant-status`, `POST /admin/rebuild-qdrant` и `scripts/recover-qdrant-collection.ps1` дают безопасный путь восстановления Qdrant из PostgreSQL после повреждения коллекции;
  - `/search`, `/search/pages`, `/ask`, `/ask/pages` принимают `nodeId/includeChildren` и `selectedTags`, фильтруют semantic + lexical retrieval по разделу и тегам документа;
  - `/ui/consult` умеет выбирать рабочий раздел, показывать документы выбранного scope и сохранять `nodeId/includeChildren` в URL;
  - `/ui/consult` показывает окно `#` с тегами текущего scope через `/tags`;
  - `/ui/pages-search` умеет выбирать рабочий раздел, показывать документы выбранного scope и передавать `nodeId/includeChildren` в page-only поиск и ответы;
  - `/ui/jobs` умеет выбирать рабочий раздел, показывать задачи выбранного scope и сохранять `nodeId/includeChildren` в URL;
  - `/ui/ingest` умеет выбирать primary-раздел и дополнительные разделы для нового импорта, передавать их в `nodeIds/primaryNodeId` и показывать очередь/историю задач выбранного scope;
  - `/ui/consult` показывает основной и дополнительные разделы в карточках документов, а источники поиска показывают `node_paths` из payload при наличии;
  - `/ui/nodes` умеет показывать дерево разделов, счётчики, документы выбранного раздела с их прямыми привязками к разделам, создавать и редактировать пользовательские разделы, перемещать разделы, массово привязывать документы к выбранному разделу, убирать выбранные документы из текущего пользовательского раздела, drag-and-drop документов на разделы, экспортировать/импортировать дерево разделов, показывать результат автоматической синхронизации payload, запускать ручную синхронизацию payload выбранного раздела и безопасно удалять только пустой пользовательский раздел;
  - `node_counters` обновляется SQL-триггерами, `/nodes` отдаёт ETag/304, включена фоновая выборочная сверка payload, а `GET /admin/knowledge-nodes-status` показывает readiness `knowledge_nodes`;
  - опасный `cascade_documents` доступен только через API с двойным подтверждением, UI оставлен в безопасном режиме удаления пустых разделов;
  - `POST /documents/:id/open-local` возвращает helper-контракт для локального открытия файлов на Windows.
- Лёгкий визуальный слой:
  - классификатор PDF-страниц `v3`;
  - `POST /search/visual` для поиска по `scheme`, `screen`, `table`, `signals`;
  - `POST /documents/:id/rebuild-visual-assets` для точечного preview/OCR;
  - локальный OCR через `tesseract`, если он установлен;
  - `POST /admin/reset-content` и `scripts/reset-rag-content.ps1` для очистки тестовой базы.

## Текущее состояние

- Docker Desktop снова поднят.
- `kb-api`, `PostgreSQL`, `Qdrant`, `Open WebUI`, `ingestion-worker` работают.
- В `kb-api` уже добавлены:
  - прогресс задач импорта;
  - пакетная индексация малыми порциями;
  - лёгкий режим PDF без preview страниц;
  - русский UI для импорта, консультанта и статусов.
- Тестовое наполнение можно полностью сбросить через `scripts/reset-rag-content.ps1`.
- После сброса рабочая база должна быть пустой: пользователь начинает новое наполнение с реальных документов.

Базовый milestone закрыт. Сейчас уже есть:

- устойчивый импорт тяжёлого реального PDF
- удобный браузерный режим вопросов по базе
- задачи импорта с прогрессом, остановкой и повтором
- очистка дублей
- защита от нерелевантных ответов без источников

## Что осталось дальше

1. Проверять retrieval и классификацию `v3` на реальных документах АСУ ТП.
   - Проверить `table`.
   - Проверить `scheme`.
   - Проверить `screen/HMI`.
   - Проверить `signals/tags`.
   - Подстроить эвристики на ваших PDF.

2. Точечно добавлять preview/OCR страниц для самых важных PDF.
   - Не для всей большой папки сразу.
   - Только для документов, где реально нужен визуальный слой.

3. Догружать следующие рабочие папки пользователя.
   - Сначала текстовый слой.
   - Потом точечные визуальные артефакты.

4. Разделы базы знаний по текущему ТЗ закрыты. Дальше по ним остаются только улучшения удобства, если появятся реальные рабочие сценарии.

## UI v2 — переход на новый дизайн

Цель — заменить 5 разрозненных служебных страниц на 3 крупных раздела:
**Чат / База знаний / Настройки**. Старый UI остаётся доступен для отката.
Подробности — в `docs/UI_V2.md`.

- **Итерация 1 (готова 2026-05-16).** Каркас навигации, переключатель
  тёмной/светлой темы, страница «Чат» с историей сессий, фильтрами по разделам
  и документам, режимы «Ответ ИИ» и «Найти страницы». Плейсхолдеры на других
  страницах нового UI. Новые таблицы `chat_sessions`, `chat_messages`. Новые
  эндпоинты `/api/v2/chat/...`. В шапках старого UI добавлена ссылка
  «Новый дизайн (β)».
- **Итерация 2 (готова 2026-05-16).** Страница «База знаний»: дерево разделов с
  inline-операциями (создать/переименовать/удалить с переносом документов в
  родителя), drop-zone и `<input webkitdirectory>` для браузерной загрузки,
  импорт по серверному пути, блок задач импорта с polling раз в 3 секунды и
  отменой, таблица документов с поиском, переключением `includeChildren`,
  редактором тегов (модалка), перемещением и удалением (двойное подтверждение).
  Новых эндпоинтов нет — переиспользованы существующие `/documents`, `/jobs`,
  `/nodes`, `/tags`, `/documents/upload`, `/documents/ingest-folder-async`,
  `/documents/bulk-link`.
- **Итерация 3 (готова 2026-05-16).** Страница «Настройки» с 6 блоками:
  модели (read-only), облачный ИИ (OpenAI-совместимый, любой провайдер по
  Base URL + API Key), сервисы (статус Postgres/Qdrant/Ollama/kb-api),
  поиск (read-only), внешний вид (тема по умолчанию через `app_settings.theme`),
  обслуживание (пересборка Qdrant, сброс содержимого с тройным подтверждением).
  В чат добавлен переключатель «🔒 Локально / ⚡ Облако» с плашкой о том, что
  фрагменты документов уйдут во внешний API. Авто-fallback отключён: при ошибке
  облака — кнопка «Переключиться на локальный ИИ» в карточке сообщения. Старый
  UI (`/ui/consult`, `/ui/ingest`, `/ui/jobs`, `/ui/pages-search`, `/ui/nodes`)
  скрыт за `?admin=1` (cookie на 1 час). Новые таблицы/колонки: `app_settings`,
  `chat_sessions.provider`. Новые эндпоинты: `/api/v2/settings/*`. Подробности
  по облаку — `docs/CLOUD_PROVIDER.md`.

## Полировка после UI v2 (готова 2026-05-16)

Точечные улучшения по живым замечаниям после трёх итераций:

- **Множественный `nodeIds` в `searchService.hybridSearch`.** Готово. И semantic,
  и lexical-ветка теперь реально фильтруют по всем выбранным разделам
  (`match: { any: [...] }` в Qdrant, `ANY($1::uuid[])` в Postgres). Старый
  параметр `nodeId` совместим.
- **Streaming ответа** для локальной Ollama и облачного провайдера. Готово.
  Новый эндпоинт `POST /api/v2/chat/sessions/:id/messages/stream` отдаёт SSE
  с событиями `meta`, `sources`, `token`, `done`, `error`. Кнопка «Отправить»
  превращается в «Стоп» во время стрима; частичный текст сохраняется в БД с
  `metadata.aborted = true`.
- **Бэкап БД из UI «Настройки».** Готово. `pg_dump | gzip` через
  `child_process.spawn`, листинг/скачивание/удаление/восстановление. Все
  эндпоинты `/api/v2/backups/*` защищены админ-флагом. Подробности —
  `docs/BACKUP_RESTORE.md`.
- **Тест облака на reasoning-моделях.** Готово. `max_tokens` поднят до 50;
  если ответ пуст, но есть `reasoning_content` / `finish_reason: length` —
  возвращается успешный результат с поясняющим текстом.

## Полировка #2 после UI v2 (готова 2026-05-16)

Пять накопленных улучшений по обратной связи с реальной работы:

- **Удаление раздела через тёмную модалку.** В `uiV2Knowledge.js`
  добавлена общая `openConfirmModal(...)`-обёртка и через неё
  переписана `confirmDeleteNode`. Для пустого раздела — стратегия
  `block`; для раздела с документами — `move_to_parent`/
  `move_to_unsorted`; раздел с потомками — informational-модалка
  со ссылкой на расширенный редактор `/ui/nodes`. UUID кодируется
  через `encodeURIComponent`.
- **Фильтры/пагинация/действия в задачах импорта.** `GET /jobs`
  расширен `statuses=running,completed,stopped`, `offset`, и
  возвращает `total`. На фронте — три пилюли-фильтра, dropdown
  размера страницы (10/25/50), пагинация. Кнопки «Продолжить»
  (через существующий `POST /jobs/:id/retry`) и «Удалить» (новый
  `DELETE /jobs/:id`). Фильтр и pageSize сохраняются в localStorage.
- **Прибитый снизу композер чата.** На `body.page-chat` `.main`
  ограничен `height: 100vh; overflow: hidden`. Внутри `chat-page__main`
  явные `flex: 0 0 auto` для шапки/composer, `flex: 1 1 auto;
  min-height: 0` для `.chat-stream`. Автоскролл срабатывает только
  если пользователь уже в самом низу. `position: fixed` не
  используется — чистый flexbox.
- **Колонка «Чанки» в таблице документов.** Между «Страниц» и
  «Раздел». Значение из `doc.chunk_count` (уже возвращается
  `listDocuments`). Для 0/null — приглушённое тире «—».
- **Компактные источники + кликабельные сноски `[N]`.** Под ответом
  ассистента вместо списка карточек — одна свёрнутая строка
  «ИСТОЧНИКИ · N фрагментов из M документов». Аккордеон группирует
  по документу. Каждая строка `[N] <короткая подпись> → открыть`.
  В тексте ответа `[1]`, `[5]` через DOM `TreeWalker SHOW_TEXT`
  заменяются на `<sup class="msg__ref"><a>[N]</a></sup>`. Клик
  раскрывает блок и подсвечивает строку 1.4-сек CSS-анимацией.
  Подсчёт `chunkCount` берётся напрямую из БД через существующий
  `COUNT(*)` — без новых колонок.

## Полировка #3 после UI v2 (готова 2026-05-17)

Восемь связанных улучшений по навигации, фильтрам, чатам, настройкам
и системному промпту.

- **A. Каскадное удаление разделов.** `confirmDeleteNode` больше не
  блокирует удаление при наличии потомков — показывает confirm-модалку
  с pluralization («N подразделов · M документов»). На бэкенде —
  новый метод `postgresProvider.deleteKnowledgeNodeCascade` и параметр
  `?cascade=true` в `DELETE /nodes/:id`. Документы переносятся в
  системный раздел «Без раздела».
- **B. Автообновление дерева.** Все мутации разделов идут через
  `refreshNodes({reloadDocuments})`. Скролл документов сохраняется.
- **C. Расширенный парсер сносок.** Регулярка теперь покрывает
  `[N]`, `[N, M]`, `[Источник N]`, `[Source N]`. Каждое число — отдельная
  плашка.
- **D. Фильтр по тегам в чате + кликабельные документы.** Новая секция
  «Теги» в правой панели. Имена документов теперь `<a target="_blank">`
  с hover-подчёркиванием. Фильтр `filters.tags` сохраняется в
  `chat_sessions.filters` (JSONB) и передаётся в
  `searchService.hybridSearch({selectedTags})`.
- **E. Группировка истории чатов по датам.** Сегодня / Вчера /
  7 дней / 30 дней / Раньше. У каждой записи — короткая дата справа
  (время для сегодня, день недели, «12 мая», «12 апр 24»).
- **F. Узкий главный сайдбар + контекстный сайдбар.** Layout перешёл
  на grid `64px 240px 1fr`. Главный сайдбар — только иконки с tooltip
  через `title`, переключатель темы переехал сюда из шапки.
  Контекстный сайдбар — per-page: чат (история), знания (дерево),
  настройки (якоря). Дерево разделов убрано из `kb-page`.
- **G. Редактируемые параметры retrieval.** Новый блок «Поиск
  (retrieval)» в `/ui/v2/settings` — semantic.top_k, bm25.top_k,
  fusion.top_k_final, reranking.enabled, reranking.candidate_pool.
  Эндпоинты `GET/PATCH/DELETE /api/v2/settings/retrieval`. Значения
  сохраняются в `app_settings.retrieval` (JSONB), переопределяют
  yaml. `appSettingsService.getRetrievalConfigSync()` для горячего
  чтения из `SearchService`.
- **H. Редактируемый системный промпт.** Новый файл
  `apps/kb-api/src/services/systemPromptService.js` с
  `DEFAULT_SYSTEM_PROMPT`, форматтерами и `renderSystemPrompt`.
  Плейсхолдеры `{sources}`, `{question}`, `{history}`. Эндпоинты
  `GET/PATCH/DELETE /api/v2/settings/system-prompt`. UI в Настройках —
  textarea + предупреждения о пропавших плейсхолдерах + длине >
  8000 символов.

## Полировка #4 после UI v2 (backend часть готова 2026-05-17)

Пять связанных улучшений: несколько облачных провайдеров, парсинг тегов
через запятую, рабочий фильтр по тегам в чате, лимиты multipart и
автообновление дерева разделов. UI-часть (горизонтальные вкладки на
страницах БЗ/Настроек, формат даты в истории, ресайз/коллапс контекстного
сайдбара) — следующим PR.

- ✅ **I. Несколько облачных провайдеров.** Хранение
  `app_settings.cloudProviders = { providers: [{id,name,baseUrl,apiKey,model}],
  defaultProviderId }` с автомиграцией старого `cloudProvider`. Новые
  эндпоинты `/api/v2/settings/cloudProviders` (CRUD + `/:id/test` +
  `/default`). `chat_sessions.provider` теперь принимает `cloud:<uuid>` и
  делает fallback на default'а при удалении выбранного. В чате старая пара
  кнопок «Локально/Облако» заменена на dropdown с активным провайдером,
  бейджем «по умолчанию» и disabled-пунктом для ненастроенных.
- ✅ **J. Парсинг тегов через запятую/`;`/`\n`.** `utils/tags.js →
  parseTagList(value)` теперь сплитит по `/[,;\n]+/`, тримит, фильтрует
  >64 символов, дедупит. Один и тот же помощник используется в фронте
  (`uiV2Knowledge.js: parseTagInput`) и в `routes/documents.js
  parseCategories`. Идемпотентная миграция `tagsNormalized` нормализует
  существующие документы при старте kb-api и синхронизирует Qdrant payload.
- ✅ **Q. Фильтр по тегам в чате реально сужает результаты.** После
  миграции теги хранятся как массив. Существующий
  `searchService.buildQdrantFilter({categories: {match: {any: [...]}}})` и
  SQL `jsonb_array_elements_text + lower(trim(...)) = ANY($::text[])`
  начинают находить совпадения.
- ✅ **L. Лимиты multipart.** В `apps/kb-api/src/index.js`
  `@fastify/multipart` теперь регистрируется с
  `limits: { files: 1000, fileSize: 524288000, fields: 20, fieldSize:
  1048576 }`. На фронте загрузка переписана на пул из 3 параллельных
  аплоадов с агрегированным toast'ом в финале.
- ✅ **P. Автообновление дерева разделов после перемещения документов.**

## Behavior changes (#8.1.c.fix-2, 2026-05-18)

### 1. БЗ → Загрузка: убраны три контрола

- **Чекбокс «Лёгкий режим (без превью страниц)»** — удалён.
  UI теперь всегда передаёт `createVisualAssets=true`. Превью
  страниц включено всегда. API (`POST /documents/ingest-folder-async`
  и др.) по-прежнему принимает `createVisualAssets: false` — для
  совместимости со скриптами на curl, но из UI этой опции нет.
- **Чекбокс «Включая вложенные папки»** — удалён. Жёстко
  `recursive=true` и для drag-n-drop, и для серверного пути.
- **Селектор «Параллелизм загрузки»** — удалён. Дублировал
  «Настройки → Сервисы → Параллелизм индексации» (этот
  единственный остался). Изменения там применяются мгновенно через
  `indexingSemaphore`. Очередь на фронте теперь всегда
  последовательная — реальный throughput считает бэкенд.

### 2. OCR для всех страниц PDF — включён по умолчанию

В `appSettingsService.getOcrSettings()` дефолт `ocrAll` переключён
с `false` на `true`. Владелец работает в основном со сканами, без
этой галки большинство PDF-страниц шли как «пустые» (текст внутри
картинки — извлечь нельзя без OCR).

При старте kb-api прогоняется одноразовая миграция
`runOcrAllDefaultTrueMigration` (флаг `ocrAllDefaultTrue` в
`app_settings.migrations`): если в БД лежит `ocrAll=false`, она
переписывает значение на `true`. Если пользователь уже выставлял
true вручную — миграция тихо помечается выполненной без изменений.
Импорт замедляется в 2–5 раз — это компромисс за полное покрытие.

Чтобы вернуть старое поведение, владелец может снять галку
вручную в Настройки → Сервисы → OCR — это сохраняется в БД и
больше не перетирается.

### 3. ByteString-баг GPT/Gemini (блокер)

При тесте подключения и в чате GPT/Gemini падал с
`Cannot convert argument to a ByteString because the character at
index N has a value of 1057 which is greater than 255`. Корень —
кириллический символ или невидимая зерошириная вставка в API-ключе
(HTTP-заголовки по RFC 7230 принимают только видимый US-ASCII).

В `CloudChatProvider` появилась обёртка
`prepareAuthorizationHeader(apiKey)`:

- Вычищает zero-width / control / BOM / биди-маркеры (через
  один regex с unicode-escape: ` --​-‏‪-‮﻿`).
- Если после очистки остался не-ASCII символ — кидает понятную
  русскую ошибку с **позицией** и кодом: «API-ключ содержит
  недопустимый символ на позиции 21 (код U+0421). HTTP-заголовки
  принимают только латиницу, цифры и ASCII-знаки. Скопируйте ключ
  заново из консоли провайдера…».

Тело запроса (system prompt, messages, model name) не трогается —
оно JSON.stringify, UTF-8 там нормально.

### 4. «Применить шаблон» — deep clone

Кнопка теперь делает `JSON.parse(JSON.stringify(profile))` и
вызывает выделенную функцию `applyTemplateToWizard(src)`, которая
переносит **все** nested-структуры: `match.required_headers`,
`match.required_sheets`, `skip_rows`, `per_sheet.<sheet>.columns`,
`cabinet.*`, `station_default.*`. Раньше код был линейным
последовательным fill — некоторые поля могли быть пропущены.

`buildsDirty` flag из #8.1.c.fix-patch по-прежнему уважается —
если пользователь уже трогал чекбоксы, шаблон их не затирает.

### 5. Password fields в `<form>` (косметика)

Вся секция «Облачные провайдеры» (`<div id="section-cloud">`)
заменена на `<form autocomplete="off" onsubmit="return false;">`.
Это убирает 16 одинаковых жалоб в DevTools Console:
`[DOM] Password field is not contained in a form`. Поведение не
меняется — onsubmit отменяет случайный submit по Enter.
