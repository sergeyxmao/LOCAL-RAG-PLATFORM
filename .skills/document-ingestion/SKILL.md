# Document Ingestion Skill

## Назначение

Этот skill используется для задач, связанных с импортом документов в локальную RAG-платформу.

Проект работает локально на Windows + Docker Desktop + WSL2.
Основной API: kb-api.
Импорт идёт из папки data/raw.

## Поддерживаемые форматы

Система уже должна учитывать форматы:

- .txt
- .md
- .pdf
- .docx
- .csv
- .xlsx
- .xls

## Основной pipeline импорта

При изменениях в импорте всегда учитывать цепочку:

1. Получение файла или папки.
2. Проверка типа файла.
3. Защита от дублей.
4. Извлечение текста.
5. Для PDF — обработка страниц.
6. Классификация PDF-страниц, если применимо.
7. Chunking.
8. Сохранение документа и chunk-ов в PostgreSQL.
9. Создание embeddings.
10. Запись в Qdrant.
11. Обновление статуса job.
12. Отображение прогресса в UI.

## Фоновые задачи

Для больших документов и папок использовать фоновые задачи:

- /documents/ingest-file-async
- /documents/ingest-folder-async

В UI статус смотреть через:

- /ui/jobs

Важные поля прогресса:

- total_items
- processed_items
- progress_message
- status
- error

## Ограничения слабого ноутбука

Проект работает на слабом ноутбуке, поэтому:

- большие PDF не обрабатывать синхронно;
- большие папки импортировать фоном;
- сначала использовать createVisualAssets=false;
- не создавать превью страниц без необходимости;
- не добавлять тяжёлые операции в основной поток запроса;
- учитывать ограниченное место на диске C:;
- избегать временных файлов без очистки.

## Ошибки диска

Уже была проблема:

No space left on device: WAL buffer size exceeds available disk space

Это связано с нехваткой места для Qdrant/WAL.

При задачах импорта учитывать:

- не создавать лишние дубли;
- не переиндексировать уже импортированные файлы без причины;
- аккуратно удалять временные файлы;
- давать понятную ошибку пользователю, если не хватает места.

## Правила для Codex

- Перед изменением логики импорта найти существующие routes/services, связанные с import/ingest/documents/jobs.
- Не переписывать импорт полностью без отдельного плана.
- Сохранять русские тексты UI.
- После изменения объяснить:
  - какие файлы изменены;
  - что именно изменено;
  - как проверить через /ui/ingest и /ui/jobs.
- Если меняется pipeline импорта, проверить, что поиск и ответы после импорта не сломались.
- Если задача связана с PDF, учитывать page_type:
  - title
  - contents
  - changelog
  - legal
  - signals
  - table
  - scheme
  - screen
  - text
