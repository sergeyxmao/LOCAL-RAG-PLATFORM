# RAG System

Использовать этот навык как рабочую инструкцию для локальной базы знаний по документам АСУ ТП.

## Основной контекст

- Считать систему локальной, без облачных зависимостей.
- Считать основным источником документов папку `data/raw`.
- Поддерживать извлечение текста из `txt`, `md`, `pdf`, `docx`, `csv`, `xlsx`, `xls`.
- Выполнять чанкинг документов перед индексацией.
- Использовать embeddings через `qwen3-embedding:0.6b`.
- Хранить метаданные, статусы и служебные записи в PostgreSQL.
- Хранить векторы и векторный поиск в Qdrant.
- Использовать semantic + lexical search.
- Формировать ответы только по найденным источникам.
- Если источников нет, возвращать честный `fallback-empty`, а не выдумывать ответ.
- Все пользовательские тексты и служебные сообщения писать на русском языке.

## Ограничения среды

- Учитывать слабый ноутбук без нормальной дискретной GPU.
- Беречь диск `C:` и не предлагать решения, которые резко увеличивают расход места.
- Для тяжёлых PDF предпочитать фоновый импорт.
- Для первого прохода по большим папкам по возможности использовать режим без `createVisualAssets`.

## Порядок проверки RAG

Если задача связана с качеством поиска или ответов, проверять цепочку по порядку:

1. Импорт документа из `data/raw`.
2. Корректность извлечения текста.
3. Чанкинг.
4. Запись метаданных в PostgreSQL.
5. Запись векторов в Qdrant.
6. Retrieval.
7. Ответ с источниками.

Не считать задачу решённой, если ответ выглядит правдоподобно, но не подтверждается найденными источниками.
