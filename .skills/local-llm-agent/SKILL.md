# Local LLM Agent Skill

## Назначение

Этот skill используется для задач, связанных с локальным ИИ-агентом проекта LOCAL-RAG-PLATFORM.

Проект работает локально и использует:

- Open WebUI как основной чат-интерфейс;
- Ollama как локальный провайдер моделей;
- qwen3:4b как текущую чат-модель;
- qwen3-embedding:0.6b как embedding-модель;
- kb-api как API для импорта, поиска и ответов;
- Qdrant + PostgreSQL как хранилище поиска и метаданных.

## Главная задача агента

Агент должен быть практическим консультантом по рабочим документам АСУ ТП.

Он должен помогать по:

- документации metsoDNA;
- функциональным блокам;
- сигналам;
- тегам;
- оборудованию;
- схемам;
- таблицам;
- PDF-страницам;
- рабочим инструкциям;
- инженерным вопросам по найденным документам.

Агент не должен быть “универсальным агентом ради агента”.
Главная ценность — точные ответы по локальной базе документов.

## Основная цепочка ответа

При вопросе пользователя система должна работать так:

1. Принять вопрос пользователя.
2. Найти релевантные источники через retrieval.
3. Собрать RAG-контекст.
4. Передать в локальную модель только нужные фрагменты.
5. Сформировать ответ на русском языке.
6. Показать источники.
7. Если источников нет — вернуть честный fallback-empty.

## Правила ответов

- Отвечать только по найденным источникам.
- Не выдумывать факты по документам.
- Если информации недостаточно, прямо сказать об этом.
- Не скрывать отсутствие источников.
- Для точных технических обозначений сохранять оригинальные имена сигналов, тегов, блоков, параметров.
- Не переводить технические коды и теги.
- Если найдено несколько возможных вариантов, перечислить их и указать источники.
- Для АСУ ТП давать практический инженерный ответ, а не общий пересказ.

## Поведение при fallback-empty

Если источников нет или они нерелевантны:

- не придумывать ответ;
- не отвечать “из общих знаний”, если режим требует ответ по базе;
- написать, что в загруженных документах ответ не найден;
- предложить уточнить документ, тег, сигнал или загрузить нужный файл.

## Ограничения локальной модели

qwen3:4b — лёгкая локальная модель.

При работе с ней учитывать:

- ограниченный контекст;
- возможные ошибки рассуждения;
- нельзя давать слишком много источников за один раз;
- промпт должен быть коротким и точным;
- важные факты лучше давать явно в RAG-контексте;
- длинные документы нельзя целиком отправлять в модель.

## Prompt building

При изменении prompt-логики учитывать:

- системная инструкция должна быть короткой;
- RAG-контекст должен быть отделён от вопроса пользователя;
- источники должны иметь понятные идентификаторы;
- модель должна понимать, что нельзя отвечать вне источников;
- итоговый ответ должен быть на русском языке.

Желательный принцип:

- сначала факты из источников;
- затем краткое объяснение;
- затем ссылки/источники;
- затем предупреждение, если данных мало.

## Open WebUI

Open WebUI используется как основной локальный чат-интерфейс.

При изменениях учитывать:

- пользователь должен получать русские ответы;
- ответы должны быть пригодны для работы инженера АСУ ТП;
- если интеграция идёт через kb-api, не ломать текущие endpoints;
- не менять модель по умолчанию без явного разрешения.

## Ollama

При работе с Ollama учитывать:

- текущая чат-модель: qwen3:4b;
- текущая embedding-модель: qwen3-embedding:0.6b;
- не скачивать и не требовать тяжёлые модели без разрешения;
- не предлагать модели, которые не потянет слабый ноутбук;
- если нужна более сильная модель, предлагать это как отдельный будущий этап.

## Производительность

Проект работает на слабом ноутбуке:

- не увеличивать контекст без необходимости;
- не добавлять многоступенчатую агентную цепочку без причины;
- не запускать несколько LLM-запросов там, где достаточно одного;
- не делать автоматический анализ всех документов по каждому вопросу;
- сначала retrieval, потом LLM.

## Правила для Codex

- Перед изменением логики агента найти файлы, связанные с answer generation, prompt, consult, Open WebUI integration, Ollama provider.
- Сначала объяснить план.
- Не переписывать весь агентный слой без подтверждения.
- Сохранять русские пользовательские тексты.
- После изменения написать:
  - какие файлы изменены;
  - что изменилось;
  - как проверить через /ui/consult и Open WebUI.
- Если изменение влияет на retrieval или индекс, указать это отдельно.
